4. ディレクトリ構成と設計思想

現在は開発の迅速性を重視し、機能を直感的に配置した構造を採用しています。今後、機能追加に伴い、関心事の分離（Separation of Concerns）を強化する設計へ移行予定です。

NEWLIFE/my-delivery-app/src/
├── App.tsx             # アプリケーションルート
├── main.tsx            # メインロジック・レンダリング
├── DeliveryManagement.tsx # 納品管理画面
├── MasterEditor.tsx    # マスタ編集画面
├── MasterManagement.tsx # マスタ一覧管理
├── Login.tsx           # 認証画面
├── supabaseClient.ts   # Supabase連携クライアント
├── masters.ts          # データベース定義・型定義
└── types.ts            # アプリケーション共通型定義

設計の意図と今後の展望

  • 現状（現在の開発フェーズ）：プロトタイプとして、各機能（Screen）へのアクセスを最優先したフラットな構造を採用。
  • 保守性への配慮：supabaseClient.ts に通信を一元化し、ロジックの肥大化を防いでいます。
  • 今後の拡張予定：機能拡大時には、これらを /components や /features ディレクトリへ再配置し、より堅牢なFeature-based Architectureへ最適化する設計思想で開発しています。
